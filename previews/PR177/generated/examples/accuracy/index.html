Accuracy and Parameters

The NFFT approximates the NDFT; its error depends on the window function $\varphi$, the window width $W$ (in grid points) and the oversampling factor $\sigma$ (see Mathematical Background). NFFT.jl lets you state the error you need and chooses these three for you.

From reltol to parameters

reltol is the requested relative error in the $\ell^2$ norm, for random data. For each combination of window family, $W$ and $\sigma$ NFFT.jl carries a table with the optimised shape parameter of the window and the error it reaches. From all entries whose predicted error is below reltol, the plan takes the one with the lowest predicted run time. The cost model weighs the resampling ($J W^D$) against the FFT ($\sigma^D |\bm{N}| \log$), so the choice depends on the dimension and on the ratio of nodes to grid size.

using NFFT, LinearAlgebra, Random, CairoMakie
Random.seed!(1)

N = (48, 48)
k = rand(2, 4000) .- 0.5
f = randn(ComplexF64, N)
exact = NDFTPlan(k, N) * f
relerr(p) = norm(p * f - exact) / norm(exact)

p = plan_nfft(k, N; reltol=1e-6)
NFFTPlan{Float64} for an input of size (48, 48) along dims 1:2 at 4000 nodes: ExpSemicircle window, W = 7, σ = 2.0, predicted error 9.97192883345134e-7

The plan shows what it chose; NFFT.parameters returns the same as a named tuple:

NFFT.parameters(p)
(window = ExpSemicircle(), W = 7, σ = 2.0)

Over a range of tolerances, the measured error stays below the requested one, and accuracy(p) predicts it well:

tols = [10.0^-i for i in 2:14]
plans = [plan_nfft(k, N; reltol=t) for t in tols]
measured = relerr.(plans)
predicted = accuracy.(plans)

fig = Figure(size=(640, 380))
ax = Axis(fig[1, 1]; xscale=log10, yscale=log10, xreversed=true,
          xlabel="requested reltol", ylabel="relative error",
          xticks=LogTicks(-14:2:-2), yticks=LogTicks(-14:2:-2))
lines!(ax, tols, tols; color=:gray60, linestyle=:dash, label="reltol")
scatterlines!(ax, tols, predicted; label="accuracy(p)")
scatterlines!(ax, tols, measured; label="measured")
axislegend(ax; position=:rt)
fig

Below about $10^{-14}$ rounding errors dominate in double precision; in single precision the floor is about $10^{-6}$. A reltol below the floor gives the most accurate plan available.

Window families

Two families have parameter tables:

  • KaiserBessel: the continuous Kaiser–Bessel window,
  • ExpSemicircle: the "exponential of semicircle" window $\exp(\beta((1-(2z/W)^2)^{e_0} - 1))$.

The default window = :auto lets both compete. A fixed family restricts the search:

pkb = plan_nfft(k, N; window=KaiserBessel())
pes = plan_nfft(k, N; window=ExpSemicircle())
NFFT.parameters(pkb), NFFT.parameters(pes)
((window = KaiserBessel(), W = 10, σ = 1.75), (window = ExpSemicircle(), W = 9, σ = 2.05))

How the error falls with the width, at $\sigma = 2$ and $\sigma = 1.25$:

Ws = 4:14
fig = Figure(size=(640, 380))
ax = Axis(fig[1, 1]; yscale=log10, xlabel="window width W", ylabel="relative error",
          xticks=Ws, yticks=LogTicks(-14:2:-2))
for (σ, style) in ((2.0, :solid), (1.25, :dash)), (win, name) in ((KaiserBessel(), "Kaiser–Bessel"),
                                                                   (ExpSemicircle(), "ES"))
  errs = [relerr(plan_nfft(k, N; window=win, W, σ)) for W in Ws]
  scatterlines!(ax, Ws, errs; linestyle=style, label="$name, σ = $σ")
end
axislegend(ax; position=:lb)
fig

A smaller $\sigma$ needs a wider window for the same error, but its FFT is cheaper; which is faster overall depends on $D$ and on the number of nodes. This is the trade-off the automatic choice makes.

Setting the parameters yourself

W and σ restrict the search as well; with both given, only the window shape comes from the table. $W$ may be odd. In the notation of the NFFT.jl paper the window has the half width $m$, so W = 2m.

p = plan_nfft(k, N; W=7, σ=1.5)
NFFT.parameters(p), relerr(p)
((window = ExpSemicircle(), W = 7, σ = 1.5), 6.13080993991677e-6)

Any other window can be used through CustomWindow. The function receives the offset $z$ in grid points and the width $W$; it must be symmetric and vanish for $|z| \ge W/2$. Without a table, W and σ must be given and accuracy(p) is unknown (NaN):

gauss = CustomWindow((z, W) -> abs(z) < W / 2 ? exp(-(2z / W)^2 * 9) : 0.0)
pg = plan_nfft(k, N; window=gauss, W=8, σ=2.0)
relerr(pg), accuracy(pg)
(6.343713256856872e-5, NaN)

FFT

The FFT on the oversampled grid uses FFTW. fft = FFTWBackend(flags=FFTW.MEASURE) lets FFTW measure its plans, which takes longer when creating the NFFT plan:

using FFTW
p = plan_nfft(k, N; fft=FFTWBackend(flags=FFTW.MEASURE))

NFFT.jl computes only the parts of the oversampled FFT that are needed: the input is zero outside the $\bm{N}$ modes, and only those modes are kept in the adjoint.

All options

keywordmeaning
reltolrequested relative error, default 1e-8
dimsdimensions to transform, see Transforms along Dimensions
eltypeFloat32 or Float64, default from the nodes
nthreadsnumber of threads, default Threads.nthreads()
window:auto, KaiserBessel(), ExpSemicircle(), CustomWindow(φ)
W, σwindow width and oversampling factor
fftFFT backend, default FFTWBackend()
tilesizeedge length of the tiles the nodes are sorted into (expert option)

The first four are part of the Abstract Interface and mean the same for every implementation; the others are specific to NFFT.jl. An unknown option is an error.
